## [1.2.0] — 2026-08-10

<sub>diff: [8723c42...38b33a1](https://github.com/obillekyle/bakery/compare/8723c42...38b33a1)</sub>

### New Features

- **orm:** enum members migrate, and the ledger stops disabling itself ([7c58337](https://github.com/obillekyle/bakery/commit/7c58337))

    **Enum member changes migrate.** `_enum` was excluded from the column diff, so changing the members was a silent no-op. It is compared against the migration ledger rather than introspection, which reports the underlying `CHECK` constraint back in three incompatible shapes and would rebuild the table forever. Verified three runs per dialect on SQLite, MySQL and Postgres: quiet before, fires on the change, quiet after.

- **cli:** --port ([4ed94c2](https://github.com/obillekyle/bakery/commit/4ed94c2))

    `--port N`, `--port=N`, `-p N`, `-p=N`, resolving flag → `PORT` → `port` in `server.config.ts` → 3000. There was no port flag before, and every framework a developer arrives from has one; an explicit argument losing to an inherited environment variable would be the surprising order, and it is also the unrecoverable one — a shell with a stale exported `PORT` is fixed by typing the flag, while the reverse leaves you working out which variable is winning.

- **core:** generate tsconfig projects, and let plugins contribute one ([1e74937](https://github.com/obillekyle/bakery/commit/1e74937))

    On every dev boot the framework writes a TypeScript project per concern into `.cache/tsconfig/` and adds a `references` entry for each to the app's root config. Core writes two: `server` carries `bun-types`, `client` does not — so `Bun.hash()` in a file bound for the browser is a **type error** rather than a runtime one. Before this, one config covered everything and it typechecked clean.

- **core:** CORS, request-body validation and server-sent events ([43a5849](https://github.com/obillekyle/bakery/commit/43a5849))

    Three additions to the request surface, none of which adds a dependency — `@bakery-framework/core` still declares none.

### Fixes

- **core:** the fromProjectDir test asserted a Windows-only invariant ([0be99b6](https://github.com/obillekyle/bakery/commit/0be99b6))

    CI's Linux runner failed it on the first push, and it would have failed on every push since the test was written — it had simply never met a Linux runner.

- **create:** a generated app typechecks, and its example POST works ([4e4348f](https://github.com/obillekyle/bakery/commit/4e4348f))

    Two things a reader hits in the first five minutes, both invisible from inside this workspace.

- **core:** a middleware may reject with response.json.* ([8277361](https://github.com/obillekyle/bakery/commit/8277361))

    The chain recognised only `instanceof Response`, so the framework's own one-envelope idiom was silently ignored coming out of a middleware. `response.json.error(401, …)` in an `/api` route answered 401; the identical line in a middleware did not stop the request at all. Measured against a running server, an auth guard written that way **served the protected page with a 200** — and on a path with no route the same bug surfaced as a 404 HTML error page with the status and message gone, which is the shape it was first reported in.

- **core:** sessions survive a framework upgrade ([d9e2c45](https://github.com/obillekyle/bakery/commit/d9e2c45))

    The session store lived under `Bakery.cacheDir`, which `checkCacheVersion` deletes on every version bump and every dev↔prod switch — so every patch release logged out every user of every app. The original argument was sound: a cache format written by an older framework must never be read by a newer one, and the version wipe is what guaranteed it.

### Docs

- re-centre on `bun create bakery`, and cover what shipped ([17392c4](https://github.com/obillekyle/bakery/commit/17392c4))

    The install page opened with "Bakery is not on npm yet" and told the reader to clone the repo. Seven packages have been published since, so the scaffolder is the supported path and the clone is now only relevant to someone changing the framework. `docs/README.md` was a table of contents fronted by a note about a docs tree withdrawn months ago — it is now an introduction: pitch, prerequisites, a quickstart that reaches a running server in two commands, the building blocks, the routing/request/middleware patterns, and the error idioms.

### Breaking Changes

- publish as @bakery-framework, restart at 1.0.0 ([60f586a](https://github.com/obillekyle/bakery/commit/60f586a))

    BREAKING CHANGE: every package moves from @bakery/* to @bakery-framework/*.

- **orm:** Field is the only column vocabulary ([681857b](https://github.com/obillekyle/bakery/commit/681857b))

    value/primary/index/unique/foreign are gone, and TableDef is TableDef<TYPE, nullable, optional> — three parameters where there were five. The two that went were positional booleans nothing outside Field.Primary() ever set.

- close the export surface before the first publish ([bd6756e](https://github.com/obillekyle/bakery/commit/bd6756e))

    The './*' fallback is gone from core, orm and cli. core now names 39 subpaths where 86 modules used to be reachable, and anything unnamed is private from the first publish.

- .cache/ is disposable and hidden, bakery/ is precious and not ([8606543](https://github.com/obillekyle/bakery/commit/8606543))

    The reverse of the old pairing, deliberately: the cache is safe to delete and the database is not, so the *hidden* one is the disposable one and a 'clean out the dotfiles' sweep does no damage. Both paths have exactly one writer.

- split the single package into a Bun workspace ([e7bfc9f](https://github.com/obillekyle/bakery/commit/e7bfc9f))

    core, orm, cli and three plugins become separate packages; core ends with no runtime dependencies. apps/example moves in beside a new apps/starter, written against public entry points only so the export surface has a second consumer that is not the one it was built for.

### New Features

- **release:** release: for majors, and branch-declared versions ([647a3e2](https://github.com/obillekyle/bakery/commit/647a3e2))

    Two things, both from the workflow you described.

- **release:** alpha/beta/rc channels ([b4bde9c](https://github.com/obillekyle/bakery/commit/b4bde9c))

    `bun run release --alpha|--beta|--rc` cuts a prerelease; no flag graduates to stable. Passing two channels is refused rather than silently picking one.

- **release:** compute the version from the commit messages ([61ca08b](https://github.com/obillekyle/bakery/commit/61ca08b))

    `bun run release` no longer needs a version argument. It reads the commits since the last tag, classifies them, and derives the bump — showing its work, because a computed version nobody can check is worse than a typed one. An explicit `bun run release 1.4.0` still overrides it.

- **cli:** make @bakery/orm an optional peer dependency ([06a5c32](https://github.com/obillekyle/bakery/commit/06a5c32))

    `bun create bakery --no-orm` wrote an app with no database and no `@bakery/orm` in its manifest — and then the CLI installed it anyway, because the CLI depended on it. The choice was cosmetic. Worse, it was load-bearing in the wrong direction: prod.ts and worker.ts imported `@bakery/orm/connection` inside a try that exits 1, so an app that genuinely lacked the package would have died at boot rather than run without a database.

- **create:** choose the ORM and plugins, by flag or by prompt ([a5c43ab](https://github.com/obillekyle/bakery/commit/a5c43ab))

    `bun create bakery my-app` scaffolded exactly one app: the ORM in, no plugins. Anyone wanting something else deleted files and edited a manifest, which is the part of scaffolding that is supposed to already be done.

- **orm:** views, and the orm/ folder layout ([c4ff6d2](https://github.com/obillekyle/bakery/commit/c4ff6d2))

    view() declares a stored SELECT with a row type, and writes are rejected at compile time — Mutation.Tables excludes them. orm/tables.ts + orm/views.ts + orm/indexes.ts is the layout db:sync generates into, so the generator owns tables and never touches hand-authored files.

- **orm:** the ledger, bulk insert, observability, transactions ([4471a5f](https://github.com/obillekyle/bakery/commit/4471a5f))

    Applied schemas are recorded in the database and diffed against, which is what makes db:rollback and db:history possible.

- **orm:** real foreign keys on all three adapters, and upsert ([2a87aa0](https://github.com/obillekyle/bakery/commit/2a87aa0))

    foreign() previously became a plain index — referential integrity in appearance only. All three adapters now emit and read back real FOREIGN KEY DDL, with ON DELETE / ON UPDATE, and Field.Foreign declares the reference on the column it constrains.

- **orm:** Field, a namespaced column vocabulary — and DISTINCT ([4336382](https://github.com/obillekyle/bakery/commit/4336382))

    Field.Int/Text/Varchar/BigInt/Json name what a column is, where value() took three positional booleans. Adding the sized and typed variants exposed two defaults bugs, both fixed here.

- **create:** create-bakery, and the 3.0.0 -> 4.0.0 release ([c106fbc](https://github.com/obillekyle/bakery/commit/c106fbc))

    bun create bakery, as an unscoped package that declares no dependencies at all — it writes files, and the framework is the last thing it should drag along. The emitted app's dependency range derives from the scaffolder's own version, so the two cannot drift.

- **core:** catch-all route segments ([b62342f](https://github.com/obillekyle/bakery/commit/b62342f))

    [...name] matches every deeper path, and yields to a real file or a more specific route so adding a page never gets shadowed by the catch-all above it. The yield stat is clamped to the directory being resolved, which is what stops a probe escaping it.
